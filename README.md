# n-dota-stats

Телеграм-бот, который следит за матчами Dota 2, показывает **показатели под твою
роль** и предлагает собственный топ-3 «лучших игроков матча». Ты поправляешь его
по тому, что показала Dota, — и на накопленных исправлениях подбираются веса
формулы.

```
Матч 8999344582 · 37:26 · поражение
Mirana · хард саппорт · 2/5/12
роль посчитана

GPM: 268 · 10-й перцентиль · медиана роли 330
Линия к 10:00: 39% · медиана роли 37
Варды: 5 обзорных, 9 сентри, снято 3 чужих · медиана роли 9
Стаки: 0 · медиана роли 2
Участие в файтах: 54%

Мой топ-3
1. Winter Wyvern (Dire) — 71.9
2. Sniper (Dire) — 64.4
3. Naga Siren (Dire) — 57.3
Ты — 9-е место из 10
```

## Почему это не очередная обёртка над чужим API

- **Показатели зависят от роли.** Керри видит добивания к 10:00, разрыв по
  нетворсу с вражеским керри и тайминги предметов; хард саппорт — варды, стаки,
  секунды контроля и использованные TP. Роль определяется сама, поправляется
  кнопкой и запоминается по связке «герой + линия».
- **Лучших называет сама игра.** Список «лучший и два кандидата» лежит в
  метаданных матча, поэтому известен по каждому матчу и спрашивать его не
  нужно. На нём же учится формула — по сотням игр, а не по десятку
  размеченных вручную.
- **Видно, где ты был.** Кнопка «тепловая карта» показывает вместо сводки
  плотность присутствия поверх настоящей карты Dota, крестами отмечены смерти.
  Под картинкой переключатель отрезка и возврат к сводке — всё в одном
  сообщении, новых постов не появляется.
- **Каждая цифра с чем-то сравнивается.** Перцентиль по этому же герою, медиана
  роли, твоё собственное среднее и соперник по линии. Голое число ничего не
  значит — 268 GPM это провал для керри и норма для пятёрки.
- **Модель MVP нормирует по герою, а не по матчу.** Поэтому саппорт с 483 GPM
  обходит керри с 771 GPM — и именно так считает сама Dota. Подробности и
  проверка — в [docs/methodology.md](docs/methodology.md).
- **Свой скорборд.** Итоги матча считаются по реплею, а не берутся из чужого
  разбора: из 18 сверяемых величин 17 совпадают с OpenDota точно по всем десяти
  игрокам. Сверка — командой `--verify`. См. [docs/replay.md](docs/replay.md).

## Запуск

```bash
export TELEGRAM_TOKEN='123456:AA...'     # обязательно, от @BotFather
export STEAM_API_KEY='...'               # желательно: steamcommunity.com/dev/apikey
export OPENDOTA_API_KEY='...'            # необязательно, снимает лимит запросов
go run ./cmd/n-dota-stats
```

Без `STEAM_API_KEY` бот работает через OpenDota — чуть медленнее и с их
очередью разбора, но полностью рабочий.

Для своего разбора реплеев добавь отдельный Steam-аккаунт:

```bash
export STEAM_BOT_USER='логин'
export STEAM_BOT_PASS='пароль'
```

Game Coordinator нужен только ради ключа реплея: в Steam Web API его нет.
Ключ постоянный и спрашивается один раз на матч за всё время — сохранённый
берётся из базы, а если матч пришёл от OpenDota, ключ приходит вместе с ним и
GC не тревожится вовсе.

**Steam Guard на этом аккаунте нужно отключить.** Библиотека не отдаёт наружу
токен после входа, поэтому с включённым Guard код пришлось бы вводить при
каждом перезапуске. Запускать Dota на аккаунте не требуется — лицензия
выдаётся сама. Проверить всю цепочку можно командой
`--gc-test <id матча>`: она получает ключ реплея, качает метаданные и печатает
разбор.

**Первым командой `/start` должен зайти ты**: админом становится первый
зарегистрировавшийся, пока в базе нет ни одного админа. Дальше новых
пользователей подтверждаешь через `/users`.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | подключиться: бот спросит ID аккаунта Dota |
| `/last`, `/match id` | разобрать последний или конкретный матч |
| `/history` | листать свои матчи стрелками, сводка меняется в том же сообщении |
| `/watch on\|off` | слежение за новыми матчами |
| `/me`, `/link`, `/forget` | настройки, смена аккаунта, удаление данных |
| `/users` | **админ**: карточки пользователей с листанием, действиями и их историей |
| `/budget` | **админ**: остаток суточного лимита Game Coordinator |
| `/stats` | **админ**: сколько накоплено и как часто формула угадывает |
| `/fit` | **админ**: пересчитать веса по ответам игры |
| `/weights` | **админ**: текущие веса |

Команды про формулу отданы админу намеренно: веса общие на бота, и пересчитывать
их каждому незачем. Обычному пользователю они не показываются в `/help` и
отвечают так же, как несуществующая команда.

Служебные запуски: `--verify <матч>` сверяет свой разбор с данными OpenDota
по каждому игроку и каждой метрике, `--fit` пересчитывает веса формулы по всей
истории, `--medians` пересчитывает медианы ролей,
`--snapshots` пересчитывает сохранённые сводки всех матчей.

Сводка матча хранится снимком: значения показателей, шапка, рейтинг формулы и
пометки, привязанные к матчу. При показе досчитываются только медиана роли и
твоё среднее — они растут со временем, и замораживать их нельзя. Поэтому
листание истории ничего не пересчитывает из реплея и ничего не пишет в базу.

## Подтверждение пользователей

Матчи подтверждённых пользователей разбираются полностью. Неподтверждённый
получает сводку по итоговой таблице сразу, а показатели из реплея появляются,
если этот матч уже скачали ради кого-то подтверждённого — то есть при игре в
одной команде с подтверждённым другом всё работает само.

**Один матч скачивается ровно один раз**, сколько бы пользователей бота в нём
ни играло: состояние разбора хранится у матча, а заявка ставится атомарным
переходом состояния. Связь с игроком при этом создаётся отдельно — в том числе
для матчей, скачанных до его регистрации. Разовый проход по всей базе —
`--relink`.

## Проверка

```bash
go test ./...
```

Тесты идут по сохранённому реальному матчу 8999344582 и не ходят в сеть:
модель воспроизводит экран Dota, роли раскладываются по пяти позициям,
перцентили сходятся с тем, что посчитала OpenDota, а декодер метаданных сверяется
с её же значениями секунд контроля и порядка прокачки.

Сводку можно посмотреть без телеграма:

```bash
go run ./cmd/n-dota-stats --dry-run --account 109779233 --match 8999344582 \
    --meta testdata/match_8999344582.meta.compressed
```

## Чего пока нет

Изменения рейтинга за матч: в публичных данных его нет вообще — проверено и по
API, и по реплею, и по файлу метаданных.

Лечение в том виде, в каком его считает Valve, воспроизвести не удалось — это
единственная величина из скорборда, которая берётся у OpenDota. Подробности и
измерения — в [docs/replay.md](docs/replay.md).
