# Роли и показатели

## Как определяется роль

Назначенной роли нет нигде: ни в Steam Web API, ни в реплее, ни в файле
метаданных. Поиск по `AssignedRole`, `SelectedRole`, `Position` ничего не даёт.
Есть только линия (`lane`, `lane_role`), которая не отличает керри от саппорта на
одной линии.

Поэтому роль выводится из поведения (`internal/analysis/role.go`):

1. Если игрок уже поправлял роль на этом герое и этой линии — берём его поправку.
2. Внутри команды сортируем по нетворсу. Саппорты — двое беднейших, но игрок с
   шестью и более вардами считается саппортом принудительно, а игрок со 150+
   добиваниями — кором принудительно.
3. Среди коров: линия 2 — мид, линия 3 — оффлейн, оставшийся — керри.
4. Среди саппортов: тот, чья линия совпала с линией керри, — хард (поз. 5),
   второй — роум (поз. 4).

Шаг 2 важнее, чем кажется. В матче 8999344582 OpenDota выставила Shadow Shaman
линию мида; без проверки по нетворсу роли всей команды разъезжаются.

Кнопка «сменить роль» под сводкой пересчитывает показатели и запоминает
поправку — в следующий раз на том же герое бот не ошибётся.

## Наборы показателей

Шапка одинаковая для всех: результат, герой, роль с пометкой источника, KDA,
медаль, место в рейтинге MVP.

| Роль | Показатели |
|---|---|
| **1 керри** | добивания к 10:00 и 20:00 · GPM · разрыв по нетворсу с вражеским керри · доля урона команды · урон по строениям · нейтралы · тайминг ботинок · смерти |
| **2 мид** | добивания к 10:00 · опыт к 10:00 · участие в убийствах команды · урон по героям · собрано рун · GPM/XPM · смерти |
| **3 оффлейн** | lane efficiency · добивания к 10:00 · секунды контроля · урон по строениям · стаки · участие в файтах · нейтралы · смерти |
| **4 роум** | варды · стаки · секунды контроля · участие в убийствах · собрано рун · XPM · участие в файтах · лечение · TP |
| **5 хард** | варды и снятые чужие · стаки · секунды контроля · лечение · байбэки · использовано TP · участие в файтах · lane efficiency |

Короткая сводка — не больше семи строк, остальное под кнопкой «подробнее».
Это проверяется тестом: `TestShortSummaryStaysShort`.

## Показатели под конкретных героев

Метрика может объявить список героев и показываться только на них — такие
строки идут в разделе «Герой». Сейчас заведены точность стрелы Мираны и крюков
Пуджа через общий помощник `skillshot`: попадания по героям из применений.

Добавление следующего героя — одна строка:

```go
skillshot("mirana_arrow", "Стрелы", 9, "mirana_arrow"),
skillshot("pudge_hook", "Крюки", 14, "pudge_meat_hook"),
```

## Маркеры

Каждая строка начинается со знака: `▲` заметно лучше базы, `▼` заметно хуже,
`▪` на уровне, `·` сравнивать не с чем. Порог — 15%, чтобы обычный разброс не
подсвечивался. Маркер опирается только на ту базу, которая показана в самой
строке: вердикт без видимого основания сбивает с толку.

## Базы сравнения

У каждого показателя объявлено, с чем его сравнивать:

| Основание | Что показывает |
|---|---|
| перцентиль по герою | твой результат против тысяч игр на этом же герое |
| медиана роли | против типичного игрока этой позиции |
| твоя история | против твоих же прошлых игр (от трёх матчей, объём выборки пишется рядом) |
| соперник по линии | против того, кто стоял напротив: добивания, опыт, золото на 10:00 |

Своя история считается **по роли или по герою**, смотря что осмысленнее.
Лечение, секунды контроля и точность умений задаются героем, а не позицией:
сравнивать лечение Мираны со своим средним по всем саппортам — значит
сравнивать её с Дазлом. Такие показатели помечены `ByHero`.

Выводится одной пометкой после значения:

```
Варды: 5 обзорных, 9 сентри · медиана роли 9 · твоё среднее 8
```

## Как добавить показатель

Одна запись в `analysis.Registry`:

```go
{
    Key: "runes", Label: "Собрано рун",
    Roles: []dota.Role{dota.RoleMid, dota.RoleRoamer},
    Needs: dota.DetailMeta,
    Compare: []CompareKind{CompareOwnHistory},
    Calc: func(c *Ctx) (Value, bool) {
        return num(float64(c.Player.RunePickups), "%d", c.Player.RunePickups)
    },
},
```

`Needs` отвечает за то, чтобы показатель не появлялся, пока нужных данных нет.
Шаблон сообщения править не нужно.
